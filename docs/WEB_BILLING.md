# 공식 웹 구독 날짜 조회 0.6.9

사용량 조회 CLI가 제공하지 않는 구독 날짜를 별도 공식 웹 창에서 읽는다. `구독 검토 → 구독 날짜 연결`에서 처음 로그인하고 결제 탭을 연다. 화면 로딩 후 자동으로 날짜를 읽으며 늦게 표시되면 `다시 조회`로 다시 읽을 수 있다. 날짜를 직접 타이핑할 필요는 없다.

웹 로그인과 CLI 연결 계정이 같다는 보장은 없다. 창에 표시된 연결 플랜·계정 해시를 참고해 **웹 계정이 현재 CLI 계정과 같은지 본인이 확인**하면 즉시 날짜가 자동 반영되고 완료 표시가 나온다. 별도 저장 버튼은 없다. 자동 계정 매칭과 창을 닫은 상태의 주기적 결제 조회는 구현하지 않았다. 사용량 자동 조회와 별개다. 잘못 연결한 계정의 날짜를 저장하지 않도록 매번 확인한다.

## 데이터 범위

- `chatgpt.com/settings/billing`, Claude 결제 설정, Grok 청구 화면의 명시적 갱신·종료 문구를 읽는다. ChatGPT 결제 포털을 직접 여는 경우 공식 Stripe billing 호스트만 허용한다.
- 2026-10-12 Chrome 로그인 화면에서 세 서비스의 갱신 문구를 실제 확인했다. 테스트 픽스처에는 형태만 사용하며 계정 이메일·결제 수단·주소·청구서 URL·채팅은 포함하지 않는다.
- 청구서의 마지막 결제일, 카드 만료, 주간 한도 초기화 시각은 다음 결제일로 사용하지 않는다. 연도 없는 날짜, 날짜가 여러 개라 모호한 문구, 과거 갱신 예정일은 추정하지 않는다.
- 종료일이 없으면 빈 항목을 채우지 않는다. 조회 실패·미제공은 이전 구독 날짜나 저장된 초기화를 삭제하지 않는다. 계정 확인에 따른 날짜 반영은 해당 필드만 갱신한다.
- 웹이 날짜만 표시하면 조회 당시 타임존의 달력 날짜로 보관한다. 시각을 제공받았다는 표시를 하지 않으며, 날짜만으로 소진 후 대기 시간을 정확한 시간 단위로 계산하지 않는다.
- 계정·플랜별로 확인 날짜, 읽은 날짜, 공식 호스트와 갱신·종료 문구만 로컬 저장한다. 웹 페이지 전체는 저장하지 않는다.

## 로그인과 제한

앱은 WebKit을 사용하며 제공자별 웹 데이터 저장소를 분리한다. 기존 Chrome·Safari의 쿠키와 인증 파일을 가져오지 않는다. 로그인은 공식 사이트가 처리하며 앱 코드가 비밀번호 입력값·쿠키·저장소·숨겨진 인증 상태를 읽지 않는다. 사이트 로그인 제한 또는 추가 인증이 있으면 사용자가 직접 완료한다. 내장 창에서 로그인할 수 없는 경우 공식 브라우저에서 확인할 수 있으나, 앱 날짜는 미확인 또는 이전 확인 값으로 유지한다. 날짜 수동 입력은 제거했다. 가격·자동 갱신 상태·검토 알림은 별도로 편집할 수 있다.

웹 사이트 UI가 변경되면 파서가 날짜를 확인하지 못할 수 있다. 실패를 0이나 새로운 결제일로 표시하지 않는다. 결제 페이지 로딩 30초, 화면 읽기 8초 제한이 있으며 초기 렌더링 지연에는 합계 약 8초의 재시도 대기를 두고 최대 다섯 번 읽기를 시도한다. 읽기마다 별도 8초 제한이 있으므로 전체 작업이 8초 안에 끝난다는 뜻은 아니다. 창을 닫으면 요청을 정리한다. 별도 Google·Apple 인증 창은 원래 창과 연결을 유지하며 모바일 본인인증을 기다리는 동안 결제 페이지 제한으로 인증을 중단하지 않는다. 결제·구독 취소·재구독·업그레이드를 자동 실행하지 않는다. 제공자가 표시하지 않는 구독 종료일이나 결제 시각을 계산하지 않는다.

## 근거

[ChatGPT 결제 관리](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform), [Claude 결제 안내](https://support.claude.com/en/articles/8325618-paid-plan-billing-faqs), [Grok 공식 FAQ](https://docs.x.ai/grok/faq)는 공식 구독 화면을 안내한다. 이 문서는 결제 날짜를 제공하는 공용 API가 있다는 주장이 아니다. 로그인 창은 [WebKit이 제공한 설정으로 새 창을 만들고](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:createwebviewwith:for:windowfeatures:)), [DOM 창 종료](https://developer.apple.com/documentation/webkit/wkuidelegate/webviewdidclose(_:))를 처리한다. WebKit의 [별도 웹 데이터 저장소](https://developer.apple.com/documentation/webkit/wkwebsitedatastore)와 [DOM JavaScript 평가](https://developer.apple.com/documentation/webkit/wkwebview/evaluatejavascript(_:in:contentworld:))를 이용한다.

0.4.9~0.4.10에서 Grok의 공식 SSO 리디렉션 호스트를 개별 허용하고, 인증 완료 뒤 알려진 시작 화면에서는 결제 화면으로 한 번만 복귀한다. 로딩·날짜 준비 진행 상태를 표시한다. 사용자에게 Grok 구독 검토 정상 동작을 확인받았다.

## Claude 초기화권 조회 (0.6.7)

혜택·초기화권 → Claude → 초기화권 조회에서 기존 Claude 웹 프로필로 공식 사용량 화면을 연다. 초기화권 영역의 보이는 문구만 읽으며 구매 크레딧·클라우드 세션 크레딧 영역은 수집하지 않는다. 같은 계정 확인 후 저장한 내역은 CLI 사용량 갱신으로 지워지지 않지만, 웹 보유량은 백그라운드 자동 갱신되지 않는다. 사용·취소·만료 이후에는 다시 조회해야 한다.

`현재 초기화 없음`과 `No resets available`처럼 명시된 문구로만 0개를 기록한다. 로딩·초기화권 영역 미표시·새로운 문구는 미확인으로 유지한다. 정확한 수량이나 만료 시각이 제공되지 않으면 추정하지 않는다. `/limit-reset`, `Reset for free`, 조직 reset API는 호출하지 않는다.

Google 인증은 `accounts.google.com`, 실제 한국 지역 이동 주소 `accounts.google.co.kr`과 기존 Apple 인증 주소로 제한한다. 별도 창은 `NSPanel.worksWhenModal`로 조회 시트가 열린 상태에서도 입력할 수 있게 한다. OAuth 팝업에는 WebKit이 준 설정을 그대로 써 opener와 로그인 저장소를 유지한다.

실계정 검증(2026-10-13): Google 한국 지역 인증을 통과해 Claude `new#settings/usage`의 `제한 초기화 → 현재 초기화 없음`을 읽고 0개를 저장했다. 공식 CLI 로그인 계정과 선택한 웹 계정의 일치 여부를 확인했다. 계정 정보와 인증 쿼리는 로그·문서에 기록하지 않았다. 초기화권이 없는 상태이므로 실제 지급권의 상세 수량·만료 표시 검증은 후속이다.
