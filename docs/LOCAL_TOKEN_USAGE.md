# 로컬 토큰 기록 집계 0.6.9

`관측 기록 → 토큰 기록 → 로컬 토큰 집계`를 켜면 Codex·Claude·Grok Build 도구가 이 Mac에 기록한 토큰 사용량을 읽는다. 오늘·최근 7일·최근 30일 합계와 날짜별 기록을 표시하며, 구독 잔여율 기록과 별도로 다룬다. 새 설치와 보호 빌드로 업그레이드할 때는 꺼져 있다. 재시작·화면 방문만으로 실행하지 않고 사용자가 켜거나 새로고침할 때만 읽는다.

## 범위와 개인정보

- Codex: `CODEX_HOME` 또는 `~/.codex` 아래 `sessions`·`archived_sessions`의 JSONL. Claude: `CLAUDE_CONFIG_DIR` 또는 `~/.claude` 아래 `projects`의 JSONL. 로그가 최근 30일에 수정된 파일을 검사하고, 토큰 이벤트 날짜로 최근 30일을 집계한다. 심볼릭 링크는 따라가지 않는다.
- 모든 로컬 프로젝트·계정의 도구 기록이다. 현재 연결한 유료 계정의 전체 사용량, 웹·다른 기기·삭제된 로그, 실제 결제 청구량이나 구독 한도 차감량을 뜻하지 않는다. Grok 웹·모바일 토큰은 확인할 수 없으며 잔여율로 환산하지 않는다.
- 숫자 사용량·시각·중복 제거용 기록 식별자만 해석한다. 원본 파일은 변경하지 않는다. 대화 내용·프롬프트·도구 입력·인증 파일을 수집·저장·전송하지 않는다. 원본 로그 읽기에 필요한 일시적인 줄 버퍼는 처리 뒤 버린다.
- 숫자와 파일 경계의 SHA-256 지문을 메모리에 캐시한다. 대화가 포함될 수 있는 파일 앞뒤의 원문은 캐시에 남기지 않는다. 집계 결과와 중복 제거 ID는 디스크에 저장하지 않으며, 켜기 설정만 앱 UserDefaults에 보관한다. 끄면 진행 중인 읽기를 취소하고 메모리 집계를 비운다.

## 계산

Codex의 누적 스냅샷을 매번 합산하지 않고 같은 스레드의 차이를 센다. 동일 누적 값과 로그 사본은 중복 계산하지 않는다. 첫 누적 값은 이전 사용분을 포함할 수 있어 마지막 응답 사용량만 센다. 기준이 부족하거나 카운터가 감소하면 부분 집계로 표시한다. 부모 스레드에서 상속한 과거 접두부와 소비량이 아닌 컨텍스트 크기 채움도 제외한다. [Codex 공식 프로토콜](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)

Claude는 응답 메시지 ID로 스트리밍·복사 기록을 묶어 큰 보고값 한 번을 센다. 입력은 일반 입력·캐시 읽기·캐시 쓰기를 포함한다. 전체 합계는 입력+출력이며 캐시를 다시 더하지 않는다. 추론도 출력의 일부이므로 별도 참고값이다. 미제공 구성은 ‘미제공’으로 표시한다. [Claude 토큰 구성](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [공식 모니터링 안내](https://code.claude.com/docs/en/monitoring-usage)

집계는 도구 로그에 보고된 값이다. CLI 버전이나 출력 기록의 누락·형식 변화 때문에 실제 처리량과 다를 수 있다. 비용을 API 단가로 계산하거나 무료·유료 구독 차감량으로 해석하지 않는다.

## 읽기와 한계

백그라운드에서 줄 단위로 읽으며 진행 상태와 취소를 제공한다. 보호 빌드는 읽기 예산 3초, 본문 약 32 MiB, 파일별 4 MiB, 보관하는 숫자 기록 10만 건을 상한으로 둔다. 파싱 중 임시 기록은 파일별 읽기 예산 안에서만 만들고 각 파일 처리 후 캐시 상한을 적용한다. 집계 기간 밖의 기록은 정리하며 Codex 누적 계산에 필요한 세션별 기준값은 유지한다. 용량이 차면 오래된 기록을 제외해 최신 기록의 집계가 멈추지 않도록 하고, 제외된 구간은 부분 집계로 표시한다. 파일 열거도 개수·시간을 제한한다. 세 소스에 예산을 나누고 최근 수정 파일부터 검사하며 큰 파일은 마지막 구간을 읽는다. 경계 확인을 위한 소량의 지문 읽기는 별도다. 읽기와 JSON 처리 중간에 시간·취소를 검사하므로 단일 OS 호출의 지연까지 정확히 3초로 끊는 보장은 아니다.

상한으로 제외된 과거 구간·파일이 있으면 ‘부분 집계’와 보호 제한 안내를 표시한다. 오늘·최근 7일·30일도 **집계한 기록의 해당 날짜 합계**이며 전체 기간의 소비량을 보장하지 않는다. 전체 로그 집계는 검증 완료 전까지 제공하지 않는다. 기존 제한 없는 토큰 집계 설정은 보호 버전 첫 실행에서 한 번 끄며, 구독 한도·저장 일정은 바꾸지 않는다.

다음 갱신은 경계 SHA-256 지문이 일치하면 추가된 부분을 읽고, 축소·교체 또는 같은 크기의 수정은 다시 검사한다. 이 최적화는 CLI의 append 방식 기록을 전제로 한다. 파일 중간을 편집하면서 길이도 늘린 경우 모든 변경을 탐지하지 못할 수 있어 앱 재실행으로 다시 집계해야 한다.

쓰기 중인 마지막 미완성 줄은 다음 검사에서 재시도한다. 4 MiB를 넘는 줄, 깨진 숫자·JSON, 읽기 실패와 부족한 기준도 제외하고 부분 집계로 알린다. 기록이 없으면 ‘미제공’으로 표시하며 소비량 0이라고 단정하지 않는다. 일시적인 Foundation 객체는 각 기록 처리 뒤 해제하고 UI 진행 갱신은 초당 최대 4회로 제한한다.

각 소스의 카드에는 찾은 파일 중 확인한 파일 수와 집계된 사용 기록 수를 표시한다. 열거 자체도 제한되므로 전체 로그 대비 정확한 백분율을 뜻하지 않는다. 상단에는 마지막 실행에 걸린 시간을 표시한다. 취소를 누르면 취소 중 상태를 보여주고 완료 후 이전 결과를 유지한다. 끄면 결과와 실행 상태를 비운다.

반복 갱신에서는 메모리에 보관한 기록을 재사용하면서 아직 확인하지 않은 파일을 추가로 검사할 수 있다. 따라서 새 사용 없이도 부분 합계와 확인 파일 수가 증가할 수 있다. 이것을 그동안 새로 소비한 토큰 수로 해석하지 않는다. 큰 파일에서 제외된 과거 구간이 모두 복원되는 것은 아니다.

## Grok Build (0.4.10)

`GROK_HOME` 또는 `~/.grok` 아래 `sessions`의 `usage.json`과 해당 `summary.json`만 읽는다. 로컬 메타데이터에서 오늘·7일·30일과 입력·출력·캐시·추론을 집계한다. 대화 JSONL·인증 파일·signals.json은 읽지 않는다. usage 파일은 1 MiB, summary는 128 KiB까지이며 기존 전체 32 MiB·3초·10만 기록 상한 안에서 처리한다. 둘 중 하나가 없거나 형식이 바뀌면 미제공/부분 집계로 표시한다.

세션 전체 합계와 모델별 합계는 더하지 않는다. `turns`의 `endedAt`으로 날짜를 정하고 `sessionId + turnNumber`로 중복을 제거한다. 입력은 캐시를 포함하며 출력에 추론을 다시 더하지 않는다. 분기 전 상속 회차는 `forked_at` 또는 생성 시각으로 제외한다. `subagent*` 세션은 부모에 반영되는 사용량과 겹치므로 별도 합산하지 않고 부분 집계로 표시한다. 부모에 아직 반영되지 않았거나 부모 기록이 없는 하위 작업은 누락될 수 있다. 완료 회차 기준으로 진행 중 사용량·삭제/되감기된 회차·모든 보조 호출을 보장하지 않는다. 원본의 `usageIsIncomplete`도 부분 집계에 반영한다.

변경되는 JSON 스냅샷을 매번 다시 읽어 이전 결과를 교체하며 반복 조회 값을 누적해서 더하지 않는다. 공식 CLI 저장 형식에 의존하므로 Grok 버전 변경 시 재검증이 필요하다.
